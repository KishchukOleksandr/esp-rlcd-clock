# Phase 0 Research: Поля налаштування поточного місця знаходження на сторінці підключення

**Feature**: `002-location-config`  
**Date**: 2026-11-18  
**Target Hardware**: Waveshare ESP32-C6-DEV-KIT-N8 (ESP32-C6, RISC-V 160 MHz, 8MB Flash, 512KB SRAM)

---

## 1. Організація вбудованого довідника населених пунктів України

- **Decision**: Розмістити структурований довідник населених пунктів України (обласні центри, Київ, Севастополь, Сімферополь та ключові міста України з їхніми еталонними широтою та довготою) безпосередньо у статичному клієнтському скрипті `components/web_server/assets/app.js` (який компілюється у Flash-пам'ять через `EMBED_TXTFILES`), а також передбачити пункт «Інший населений пункт (ввести вручну)» та можливість редагування полів назви, широти й довготи перед збереженням.
- **Rationale**:
  1. Працює повністю автономно (офлайн) при підключенні смартфона або ноутбука до точки доступу `"ESP Weather Clock"` без доступу до Інтернету (`FR-009`, `SC-005`).
  2. Не витрачає жодного байта оперативної пам'яті SRAM (512KB) на мікроконтролері, оскільки статика віддається напряму з `.rodata` у 8MB Flash.
  3. Дозволяє як швидкий вибір зі списку міст України з миттєвою автопідстановкою координат (`FR-001`, `FR-002`), так і точне ручне введення для невеликих містечок або сіл України.
- **Alternatives considered**:
  - *Зовнішній онлайн-сервіс геокодування (Open-Meteo Geocoding API / Nominatim)*: Відхилено, оскільки під час первинного налаштування через Captive Portal точки доступу пристрій користувача не має доступу до Інтернету.
  - *Повна база всіх ~30 000 населених пунктів України у пам'яті МК*: Відхилено, оскільки це займе кілька мегабайтів Flash та ускладнить передачу й рендеринг у мобільному браузері; поєднання списку основних міст України з можливістю ручного вводу/коригування координат оптимально балансує зручність та компактність.

## 2. Представлення та збереження географічних координат у NVS

- **Decision**: У C-структурі конфігурації використовувати тип `double` (або `float`) для зручної роботи прикладних підсистем, а в енергонезалежній пам'яті ESP-IDF NVS зберігати широту та довготу як знакові 32-бітні цілі числа у мікроградусах (`int32_t`, помножені на `1 000 000`, ключі `"loc_lat_u6"` та `"loc_lon_u6"`), разом із прапорцем `"loc_set"` (`uint8_t`) та рядком назви `"loc_name"` (`char[65]`, до 64 байтів UTF-8).
- **Rationale**:
  1. NVS API (`nvs_flash`) має нативну атомарну підтримку `int32_t` (`nvs_set_i32` / `nvs_get_i32`) без потреби у `blob` для чисел із плаваючою комою.
  2. Точність $10^{-6}$ градуса (1 мікроградус $\approx 0{,}11\text{ м}$ на поверхні Землі) значно перевищує вимоги будь-яких метеорологічних сервісів та розрахунків сходу/заходу сонця.
  3. Буфер `64` байти UTF-8 дозволяє зберігати українські назви до ~32 кириличних символів (наприклад, `"Кам'янець-Подільський"`, `"Івано-Франківськ"`), гарантуючи фіксований розмір у пам'яті (Principle III Конституції).
- **Alternatives considered**:
  - *Зберігання координат у вигляді текстових рядків у NVS*: Потребує повторного парсингу `strtod()` при кожному читанні з NVS і чутливе до форматування.
  - *Зберігання сирого `double` через `nvs_set_blob`*: Додає накладні витрати метаданих blob-записів у сторінках NVS порівняно з примітивним `i32`.

## 3. Міграція схеми NVS (`schema_ver: 1 → 2`) та скидання налаштувань

- **Decision**: Підняти константу `CONFIG_STORE_SCHEMA_VERSION` з `1` до `2`. Якщо під час `config_store_load()` у NVS виявлено `schema_ver == 1`, зберегти наявні параметри Wi-Fi (`sta_configured`, `sta_ssid`, `sta_password`, `ap_password`), ініціалізувати поля місця знаходження значеннями за замовчуванням (`loc_configured = false`, `loc_name = ""`, `latitude = 0.0`, `longitude = 0.0`) і оновити версію схеми до `2`. При виклику `config_store_factory_reset()` (утримання кнопки `BOOT` $\ge 3\text{ с}$ або `POST /api/wifi/reset`) очищувати як мережеві налаштування, так і параметри місця знаходження (`FR-010`).
- **Rationale**: Забезпечує безшовне оновлення пристроїв, які вже були налаштовані на прошивці `001-wifi-apsta-web-config`, без втрати підключення до домашнього Wi-Fi роутера (Principle IV Конституції).
- **Alternatives considered**:
  - *Повне стирання NVS при зміні `schema_ver`*: Призвело б до скидання Wi-Fi налаштувань користувача при оновленні прошивки.

## 4. Незалежне збереження локації через HTTP REST API

- **Decision**: Виділити окремий ендпоінт `POST /api/location` (та `GET /api/location`, плюс включення об'єкта `"location"` у відповідь `GET /api/status`). Обробник `POST /api/location` валідує JSON-тіло (`name`, `latitude`, `longitude`), записує дані через `config_store_save_location()` та оновлює кеш у RAM без звернення до `wifi_manager`.
- **Rationale**: Повністю відокремлює життєвий цикл налаштування локації від мережевого з'єднання (`FR-007`, `SC-004`). Користувач може змінювати місто або уточнювати координати скільки завгодно разів без повторного введення пароля Wi-Fi та без розриву поточної HTTP-сесії.
- **Alternatives considered**:
  - *Об'єднання збереження локації з `POST /api/wifi/connect`*: Порушує вимогу `FR-007` та рішення сесії уточнень (`Q2: A` — окремий блок із власною кнопкою збереження).
