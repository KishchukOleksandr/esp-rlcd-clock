**Feature**: `003-online-ukraine-cities`  
**Date**: 2026-11-25  
**Persistence Impact**: Зміна схеми NVS **не потрібна** — зберігається існуюча схема `schema_ver = 2` (`"wifi_cfg"`), реалізована у `002-location-config`.

## 1. Тимчасові (Runtime) структури онлайн-пошуку (`components/geo_search/include/geo_search.h`)

### 1.1 `geo_search_item_t` (Результат онлайн-пошуку локації)

Представляє один населений пункт України, знайдений зовнішнім сервісом геокодування для відображення у списку вибору користувача. Зберігається лише у тимчасовому буфері на час обробки запиту (у NVS не записується).

| Поле | Тип (C11) | Розмір / Обмеження | Опис |
|------|-----------|--------------------|------|
| `name` | `char[LOC_NAME_MAX_LEN + 1]` | `1..64` байти UTF-8 + `'\0'` | Назва населеного пункту українською мовою (наприклад, `"Вишневе"`). Підставляється у поле назви форми (`FR-005`). |
| `admin1` | `char[GEO_ADMIN_MAX_LEN + 1]` | `0..64` байти UTF-8 + `'\0'` | Адміністративна одиниця 1-го рівня — область або місто зі спеціальним статусом (наприклад, `"Київська область"`). Показується лише у списку результатів (`FR-004`). |
| `admin2` | `char[GEO_ADMIN_MAX_LEN + 1]` | `0..64` байти UTF-8 + `'\0'` | Адміністративна одиниця 2-го рівня — район або громада (наприклад, `"Бучанський район"`), може бути порожнім. Показується лише у списку результатів (`FR-004`). |
| `latitude` | `double` | `-90.0 <= lat <= 90.0` (скінченне число) | Географічна широта населеного пункту. |
| `longitude` | `double` | `-180.0 <= lon <= 180.0` (скінченне число) | Географічна довгота населеного пункту. |

Константи обмежень:
- `GEO_SEARCH_MAX_RESULTS = 10` — максимальна кількість кандидатів у відповіді (обмежує розмір JSON і споживання SRAM).
- `GEO_QUERY_MIN_CHARS = 2` — мінімальна кількість UTF-8 символів у пошуковому запиті (`FR-011`).
- `GEO_QUERY_MAX_BYTES = 64` — максимальна довжина вхідного пошукового запиту в байтах UTF-8.
- `GEO_ADMIN_MAX_LEN = 64` — максимальна довжина рядка `admin1` / `admin2` в байтах UTF-8.

### 1.2 `geo_internet_status_t` (Стан доступності Інтернету)

Синхронізований м'ютексом стан фактичної доступності Інтернету на платі ESP32 (`FR-002`).

| Поле | Тип (C11) | Опис |
|------|-----------|------|
| `available` | `bool` | `true`, якщо остання фактична перевірка (або успішний онлайн-пошук) підтвердила вихід в Інтернет при активному STA; `false` в іншому випадку. |
| `checked` | `bool` | `true`, якщо після останнього підключення STA вже виконано щонайменше одну перевірку доступності. |
| `checking` | `bool` | `true`, поки фонова задача виконує перевірку доступності. |
| `last_check_uptime_sec` | `int64_t` | Час (`esp_timer_get_time() / 1000000`) останньої перевірки для діагностики та логування. |

#### Переходи стану `geo_internet_status_t`

```text
[Boot / SoftAP only / STA Disconnected]
    available = false, checked = false, checking = false
        │
        │  (подія WIFI_FSM_EV_STA_GOT_IP)
        ▼
[STA Connected → Checking]
    available = false, checked = false, checking = true
        │
        ├── TCP probe до geocoding-api.open-meteo.com:443 успішний ──▶ [Online]
        │       available = true, checked = true, checking = false
        │
        └── TCP/DNS probe не вдався (таймаут / роутер без Інтернету) ─▶ [STA No Internet]
                available = false, checked = true, checking = false
                (повторна фонова перевірка кожні 30 с, поки STA активний)
        │
        │  (подія WIFI_FSM_EV_STA_DISCONNECTED або Factory Reset)
        ▼
[STA Disconnected]
    available = false, checked = false, checking = false
```

## 2. Збережені налаштування локації (Без змін — успадковано з `002-location-config`)

### `location_config_t` (`components/config_store/include/config_store.h`)

| Поле | Тип (C11) | Обмеження | NVS-ключ (`"wifi_cfg"`) |
|------|-----------|-----------|-------------------------|
| `configured` | `bool` | `true` після збереження, `false` після скидання | `loc_cfg` (`u8`) |
| `name` | `char[65]` | `1..64` байти UTF-8 без керівних символів | `loc_name` (`str`) |
| `latitude` | `double` | `-90.0 .. 90.0` (скінченне число) | `loc_lat` (`str`) |
| `longitude` | `double` | `-180.0 .. 180.0` (скінченне число) | `loc_lon` (`str`) |

**Зв'язок сутностей**:
- Користувач обирає один запис `geo_search_item_t` зі списку результатів онлайн-пошуку.
- Веб-інтерфейс переносить у форму поля `name` (лише назву населеного пункту без `admin1`/`admin2` згідно з `FR-005`), `latitude` та `longitude`.
- При натисканні «Зберегти місце знаходження» існуючий маршрут `POST /api/location` валідує дані за тими самими правилами (`FR-010`) і атомарно зберігає їх у `location_config_t` (NVS).

## 3. Правила валідації та фільтрації

1. **Вхідний пошуковий запит (`q`)**:
   - Обрізаються початкові та кінцеві пробіли.
   - Заборонені керівні символи ASCII (`< 0x20`, `0x7F`).
   - Кількість кодових точок UTF-8: `>= 2` (`FR-011`).
   - Довжина у байтах UTF-8: `<= 64`.
2. **Елементи зовнішньої відповіді Open-Meteo**:
   - Пропускаються всі елементи, де `country_code` відсутній або не дорівнює `"UA"` (регістронезалежно або точно `"UA"` — `FR-003`).
   - Пропускаються елементи без непорожнього `name` або з нескінченними / позадіапазонними `latitude` (`-90..90`) / `longitude` (`-180..180`).
   - Поля `name`, `admin1`, `admin2` очищуються від керівних символів та за потреби безпечно обрізаються по межі UTF-8 символу до `64` байтів.
   - Максимум повертається `GEO_SEARCH_MAX_RESULTS` (`10`) записів у порядку релевантності/населення, який повертає Open-Meteo (`FR-001`).
